## Значимые изменения

- **React 19.3.0** — <ViewTransition> стал стабильным. Он анимирует enter/exit/update/share через View Transition API, но только для обновлений-переходов: startTransition, раскрытие Suspense, useDeferredValue. Через addTransitionType внутри startTransition можно выбрать анимацию по причине перехода. Если обернуть <Suspense> в <ViewTransition>, анимируется смена fallback на контент. ([источник](https://react.dev/blog/2026/09/09/react-19-3))
- **React 19.3.0** — Fragment Refs стабильны. <Fragment ref> отдаёт FragmentInstance с методами addEventListener/removeEventListener/dispatchEvent, focus/focusLast/blur, observeUsing (Intersection/ResizeObserver), getClientRects и scrollIntoView. Это замена обёрточному <div>. ([источник](https://react.dev/blog/2026/09/09/react-19-3))
- **React DOM 19.3.0** — use(browser()) — штатный отказ от SSR для компонента. На сервере компонент приостанавливается, и в HTML попадает fallback ближайшего Suspense. Заменяет паттерн isClient + useEffect и проверки typeof window. Вызов можно ставить в условие. ([источник](https://react.dev/reference/react-dom/browser))
- **React DOM 19.3.0** — Поддержка Trusted Types: объекты TrustedHTML и TrustedScript больше не приводятся к строке, поэтому CSP require-trusted-types-for работает с React. ([источник](https://react.dev/blog/2026/09/09/react-19-3))
- **React (RSC) 19.3.0** — <Context>, импортированный из модуля с 'use client', можно рендерить прямо в Server Component. Отдельная клиентская обёртка-Provider больше не нужна. RSC также передаёт Error.cause и AggregateError.errors и поддерживает <Activity> во Flight. ([источник](https://react.dev/blog/2026/09/09/react-19-3))
- **React 19.3.0** — Изменения поведения. Transitions рендерятся независимо: медленный переход не задерживает остальные. Strict Mode дублирует эффекты и при гидратации. Обновления от resize батчатся до следующего кадра. После автосброса формы срабатывает onReset. В событии submit есть submitter. Добавлены onFullscreenChange и onFullscreenError. ([источник](https://github.com/react/react/releases/tag/v19.3.0))
- **React Compiler / eslint-plugin-react-hooks 1.0.0 / 7.1.1** — Новых стабильных релизов не было. Есть ловушка: ESLint-плагин 7.1.x содержит более новый компилятор, чем babel-plugin-react-compiler 1.0.0. Поэтому линтер может пропустить код, который компилятор при сборке молча не оптимизирует. В Next.js появился экспериментальный Rust-порт компилятора. ([источник](https://github.com/react/react/issues/37789))
- **Next.js 16.3** — Добавлены catchError из next/error (error boundary с retry(), не мешает notFound и redirect), root params (next/root-params), import.meta.glob в Turbopack и поддержка TypeScript 7 в next build. Появились Instant Navigations: Partial Prefetching и новый ISR с мгновенным shell. Экспериментально: Rust React Compiler и useOffline. ([источник](https://nextjs.org/blog/next-16-3))
- **Next.js 16.4** — Cache Components ('use cache' + Partial Prefetching) рекомендованы для всех приложений и включены по умолчанию в create-next-app, в Next.js 17 станут дефолтом. Неявное кэширование заменяется явным. Добавлены export const ensureStatic и функции navigation()/prefetch() из next/cache. В комплекте React 19.3. ([источник](https://nextjs.org/blog/next-16-4))
- **React Router 8.3.0** — href() и generatePath() кодируют параметры по RFC 3986. Пакеты допускают typescript@7. Unstable RSC: поддержка CSP nonce и SRI. ([источник](https://reactrouter.com/changelog))
- **React Router 8.4.0** — Внутренний контекст разбит на четыре, поэтому лишних ререндеров меньше: компонент только с useLocation не ререндерится при смене navigation.state. Для UNSAFE_-контекстов это ломающее изменение. Unstable: новый матчер маршрутов с unstable_validateParams. Опция createStaticRouter({ branches }) объявлена устаревшей. Документация рекомендует считать каждую RSC Server Function публичным эндпоинтом. ([источник](https://reactrouter.com/changelog))
- **Vite 8.2** — Появилась верхнеуровневая опция input вместо build.rolldownOptions. Добавлены предупреждения о возможностях конфига, которые не поддерживает нативный загрузчик, и экспорт типа конфигурации PostCSS. ([источник](https://x.com/vite_js/status/2082871231523459218))

## Затронутые вопросы

### Что такое фрагменты и зачем они нужны? (`fragments`)

С React 19.3 Fragment принимает не только key, но и ref и отдаёт FragmentInstance: события, фокус, observeUsing, getClientRects, scrollIntoView. Это закрывает частый довод в пользу обёрточного div: «нужно навесить обработчик, наблюдатель или фокус на группу элементов». В упражнения стоит добавить сценарий, где обёртку заменяет <Fragment ref>.

**Правка вопроса:** В «Кратко» заменить «если нужен `key` … используется полная форма `<Fragment key={...}>`» на «если нужен `key` (в списке) или, с React 19.3, `ref`, используется полная форма `<Fragment>`; ref на фрагменте даёт FragmentInstance (addEventListener, focus, observeUsing, getClientRects, scrollIntoView) и заменяет лишний обёрточный `<div>`».

### Почему возникают ошибки гидрации и как их исправлять? (`hydration-mismatch`)

В React 19.3 появился штатный способ отказаться от SSR для части дерева — use(browser()). На сервере компонент приостанавливается, и в HTML уходит fallback ближайшего Suspense. Это официальная замена паттерну isClient + useEffect и проверкам typeof window. Упражнение с хуком useIsClient остаётся рабочим, но в объяснении нужно упомянуть новый рекомендуемый вариант. Стоит добавить вариант ответа с use(browser()).

**Правка вопроса:** Дописать в «Кратко»: «Для частей UI, которые имеют смысл только в браузере, с React 19.3 используют `use(browser())` внутри Suspense-границы: сервер отдаёт fallback, клиент рендерит компонент без расхождения. Это заменяет паттерн isClient + useEffect и проверки typeof window».

### Что такое хук use и чем он отличается от остальных хуков? (`use-hook`)

Помимо промиса и контекста, use с React 19.3 принимает browser() из react-dom, чтобы пропустить рендер компонента на сервере. Как и прочие вызовы use, его можно ставить в условие. Отдельно появилось предупреждение о неправильном использовании use в условии, и это стоит учесть в объяснениях.

**Правка вопроса:** В «Кратко» заменить «`use(resource)` читает значение промиса или контекста во время рендера» на «`use(resource)` читает значение промиса или контекста во время рендера (с React 19.3 также `use(browser())` — отказ от SSR для компонента)».

### Что такое React Server Components? (`server-components`)

С React 19.3 <Context>, импортированный из 'use client'-модуля, можно рендерить прямо в Server Component. Раньше обязательной была отдельная клиентская обёртка-Provider. Это частый вопрос: «как передать контекст в приложении на RSC». Ответ теперь короче, но значение пропса по-прежнему должно сериализоваться.

**Правка вопроса:** Дописать: «С React 19.3 контекст можно предоставлять прямо из Server Component: `<ThemeContext value="dark">`, где ThemeContext импортирован из модуля с 'use client'; значение должно быть сериализуемым, отдельный клиентский Provider-компонент не нужен».

### Какие угрозы безопасности актуальны для современного React-приложения? (`security-advanced`)

React 19.3 больше не приводит объекты TrustedHTML и TrustedScript к строке. Поэтому CSP require-trusted-types-for теперь можно применять в React-приложении как защиту от DOM-XSS. Это пополняет список мер многоуровневой защиты, который обсуждают на собеседовании.

**Правка вопроса:** В перечень мер защиты дописать: «Trusted Types (CSP `require-trusted-types-for 'script'`) — с React 19.3 поддерживаются, `dangerouslySetInnerHTML` принимает TrustedHTML из политики санитизации».

### Как работают useTransition и startTransition? (`use-transition`)

С React 19.3 transitions рендерятся независимо: медленный переход больше не задерживает остальные, раньше они объединялись. Кроме того, transition стал триггером анимаций <ViewTransition>: анимируются только обновления в startTransition, а addTransitionType задаёт тип анимации. Объяснения о группировке переходов нужно обновить.

**Правка вопроса:** Дописать: «С React 19.3 несколько transitions рендерятся независимо, медленный не задерживает остальные. Обновления в transition также запускают анимации `<ViewTransition>`, а `addTransitionType` внутри startTransition выбирает тип анимации».

### Что такое React Compiler и нужны ли теперь useMemo и useCallback? (`react-compiler`)

Стабильный компилятор по-прежнему 1.0.0, а eslint-plugin-react-hooks 7.1.x содержит более новую версию компилятора. Линтер может пропустить код, который компилятор при сборке молча не оптимизирует, поэтому при внедрении версии нужно синхронизировать. В Next.js 16.3+ есть экспериментальный Rust-порт (reactCompiler: true + experimental.turbopackRustReactCompiler).

**Правка вопроса:** Дописать: «Практическая ловушка: eslint-plugin-react-hooks 7.1.x собран с более новым компилятором, чем babel-plugin-react-compiler 1.0.0, поэтому «зелёный» линтер не гарантирует, что компонент оптимизирован. Это проверяют в DevTools (бейдж Memo ✨). В Next.js 16.3+ есть экспериментальный Rust-порт компилятора».

### Как устроен роутинг в React Router v7? (`react-router`)

Актуальная мажорная версия React Router — v8 (8.4.0), а вопрос сформулирован про v7. В 8.4 внутренний контекст разделён на четыре, и компоненты, которые читают только useLocation, не ререндерятся при смене navigation.state. Формулировку нужно сверить с v8; ответы про loader и actions остаются верными.

**Правка вопроса:** Заменить в заголовке и «Кратко» «React Router v7» на «React Router v7+ (актуально v8)». Перед этим сверить описание трёх режимов с документацией v8.
