# React Refresher

100 актуальных вопросов для собеседования на React-разработчика: 20 Junior, 40 Middle, 40 Senior.
Обновлённая и расширенная версия списка «React JS: 50 вопросов на собеседование» (`docs/react-50-questions-old.pdf`)
под React 19.2, Server Components и React Compiler.

## Что внутри

- **Каталог** — фильтры по уровню и теме (в URL), поиск по тексту и номеру, у каждого вопроса: краткий ответ,
  подробный разбор с примерами на TypeScript, подводные камни, «что спросят дальше», ссылки на react.dev.
- **Тренировка** — карточки по выбранным уровням и темам, режимы таймера (без таймера / мягкий / жёсткий),
  самооценка «Знаю / Частично / Не знаю», итог и повтор слабых вопросов. Клавиши: `Пробел` — ответ, `1`–`3` — оценка.
- **Мок-собеседование** — подборка под грейд (пропорция уровней, разные темы, от простого к сложному),
  общий таймер, заметки, эталон с уточняющими вопросами, отчёт по темам и вердикт.
- **О проекте** — таблица соответствия: куда переехал каждый из 50 старых вопросов.
- Быстрый поиск `⌘K` / `/`, светлая, тёмная и системная темы, адаптивная вёрстка.

## Запуск

Нужен Node.js 22.18+ (скрипты пакетов запускают `.ts` напрямую).

```bash
npm install
npm run dev
```

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер веб-версии (Vite) |
| `npm run build` | проверка типов всего монорепо и production-сборка веба в `apps/web/dist/` |
| `npm test` | тесты Vitest во всех пакетах |
| `npm run check` | типы + oxlint + тесты |
| `npm run bundle:content` | JSON-бандл контента для мобильного приложения → `packages/content/dist/content.json` |

## Как устроен проект

Монорепо на npm workspaces. Контент и логика общие для веба и будущего мобильного приложения.

```text
apps/
  web/                  веб-версия: Vite SPA, страницы, компоненты, загрузка вопросов через import.meta.glob
packages/
  content/              @rr/content — всё, что можно выучить
    questions/          вопросы в Markdown: junior-1.md … senior-4.md
    exercises/          упражнения в YAML, по темам
    src/
      parse.ts          разбор Markdown в объекты Question
      build.ts          сборка и нумерация вопросов (не зависит от бандлера)
      exercises.ts      Zod-схема упражнений (точка входа @rr/content/exercises)
      node.ts           загрузка вопросов и упражнений с диска (@rr/content/node)
      topics.ts, types.ts, legacy.ts
    scripts/bundle.ts   сборка JSON-бандла с версией-хешем
    scripts/generate.ts черновики упражнений через Claude, approve.ts — перенос в банк
  core/                 @rr/core — логика без UI: интервальное повторение, проверка ответов, путь, ход урока, XP
apps/mobile/            приложение на Expo (iOS): путь, уроки, повторение, профиль; прогресс в SQLite
```

### Как добавить или изменить вопрос

Вопросы лежат в `packages/content/questions/<level>-<n>.md`. Порядок файлов и вопросов в них задаёт нумерацию.

````markdown
# Текст вопроса?
@slug kebab-case-id
@topic hooks
@legacy 36
@verified react@19.2
@updated 2026-10

> Краткий ответ — 2–4 предложения, которые стоит сказать в первые 30 секунд.

Подробное объяснение: абзацы, списки, таблицы, блоки кода ```tsx.

### Подводные камни
- …

### Что спросят дальше
- …

### Ссылки
- [Название](https://react.dev/...)
````

`@topic` — один из id в `packages/content/src/topics.ts`, `@legacy` — необязательный номер вопроса из старого PDF,
`@verified` и `@updated` — необязательные: для каких версий и когда материал сверялся с документацией.
После правок запустите `npm test`: тесты проверят количество вопросов по уровням, уникальность slug,
обязательные поля, закрытые блоки кода и то, что рендер не оставляет «сырой» Markdown.

### Как добавить упражнение

Упражнения лежат в `packages/content/exercises/<тема>.yaml` — список объектов. Типы: `predict-output`, `find-bug`,
`parsons`, `fill-tokens`, `order` (`timeline` или `recipe`), `choose-tool`. Поля и проверки описаны в
`packages/content/src/exercises.ts`. Схема ловит частые ошибки: ответ вне списка вариантов, строка бага за пределами
кода, число пропусков `___` не совпадает с числом токенов. Примеры каждого типа — в `exercises/hooks.yaml`.

### Генерация упражнений с помощью Claude

Черновики упражнений по вопросам банка делает скрипт: Claude пишет упражнения (structured outputs, проверка
Zod-схемой), второй проход — ревьюер — проверяет правильность ответов, исправляет или отбрасывает спорное.
На каждый вопрос — карточка с вариантами (`quiz`, альтернатива ответу своими словами) и 2–3 практических задания.

```bash
npm run generate -w @rr/content -- --dry-run --only keys   # посмотреть промпты, без запросов
npm run generate -w @rr/content -- --only keys,rules-of-hooks
npm run generate -w @rr/content -- --topic hooks --concurrency 3
```

Ключ: скопируйте `.env.example` в `.env` в корне репозитория и впишите `ANTHROPIC_API_KEY` (файл в `.gitignore`, в приложение ключ не попадает). Подойдёт и переменная окружения или профиль `ant auth login`. В конце скрипт печатает расход токенов и стоимость.

Черновики появляются в `packages/content/exercises/drafts/<slug>.yaml` с замечаниями ревьюера в комментариях.
Вычитайте и поправьте их, затем перенесите в банк:

```bash
npm run approve -w @rr/content -- --only keys
```

`npm test` проверяет и банк, и черновики: схему, ссылки на вопросы, уникальность id.

## Деплой на Vercel

Веб-версия — статическое SPA в `apps/web`. В настройках проекта на Vercel укажите **Root Directory** `apps/web`:
Vercel сам определит Vite и npm workspaces, а `apps/web/vercel.json` перенаправит все пути на `index.html`.

## Источники

Ответы опираются на [react.dev](https://react.dev) и документацию упомянутых библиотек. Проект не связан с Meta и
командой React. Идеи режимов таймера и тренировки — из проекта [popmath](https://github.com/kirillchistov/popmath).
