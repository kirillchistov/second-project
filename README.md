# React Refresher

140 актуальных вопросов для собеседования на React-разработчика: 26 Junior, 60 Middle, 54 Senior.
Обновлённая и расширенная версия списка «React JS: 50 вопросов на собеседование» (`docs/react-50-questions-old.pdf`)
под React 19.2, Server Components и React Compiler.

## Что внутри

- **Каталог** — фильтры по уровню и теме (в URL), поиск по тексту и номеру, у каждого вопроса: краткий ответ,
  подробный разбор с примерами на TypeScript, подводные камни, «что спросят дальше», ссылки на react.dev.
- **Тренировка** — карточки по выбранным уровням и темам, режимы таймера (без таймера / мягкий / жёсткий),
  самооценка «Знаю / Частично / Не знаю», итог и повтор слабых вопросов. Клавиши: `Пробел` — ответ, `1`–`3` — оценка.
- **Мок-собеседование** — подборка под грейд (пропорция уровней, разные темы, от простого к сложному),
  общий таймер, заметки, эталон с уточняющими вопросами, отчёт по темам и вердикт.
- **О проекте** — таблица соответствия: куда переехал каждый из 50 старых вопросов.
- Быстрый поиск `⌘K` / `/`, светлая, тёмная и системная темы, адаптивная вёрстка.

## Запуск

Нужен Node.js 22.18+ (скрипты пакетов запускают `.ts` напрямую).

```bash
npm install
npm run dev
```

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер веб-версии (Vite) |
| `npm run dev:pages` | демо-путь для GitHub Pages: уроки в браузере, прогресс в localStorage |
| `npm run build` | проверка типов всего монорепо и production-сборка веба в `apps/web/dist/` |
| `npm run build:pages` | статическая сборка демо; `VITE_BASE` задаёт подкаталог (`/имя-репозитория/`) |
| `npm test` | тесты Vitest во всех пакетах |
| `npm run check` | типы + oxlint + тесты |
| `npm run bundle:content` | JSON-бандл контента для мобильного приложения → `packages/content/dist/content.json` |

## Как устроен проект

Монорепо на npm workspaces. Контент и логика общие для веба и будущего мобильного приложения.

```text
apps/
  web/                  веб-версия: Vite SPA, страницы, компоненты, загрузка вопросов через import.meta.glob
packages/
  content/              @rr/content — всё, что можно выучить
    questions/          вопросы в Markdown: junior-1.md … senior-4.md
    exercises/          упражнения в YAML, по темам
    src/
      parse.ts          разбор Markdown в объекты Question
      build.ts          сборка и нумерация вопросов (не зависит от бандлера)
      exercises.ts      Zod-схема упражнений (точка входа @rr/content/exercises)
      node.ts           загрузка вопросов и упражнений с диска (@rr/content/node)
      topics.ts, types.ts, legacy.ts
    scripts/bundle.ts   сборка JSON-бандла с версией-хешем
    rubrics/            рубрики устных ответов для ИИ-проверки
    radar/              отчёты радара изменений
    scripts/            generate.ts (упражнения), rubrics.ts, radar.ts, approve.ts — работа с контентом через Claude
  core/                 @rr/core — логика без UI: интервальное повторение, проверка ответов, путь, ход урока, XP
apps/mobile/            приложение на Expo (iOS): путь, уроки, повторение, профиль; прогресс в SQLite
apps/api/               ИИ-прокси на Hono: оценка ответа по рубрике и наводящие подсказки (Claude)
```

### Как добавить или изменить вопрос

Вопросы лежат в `packages/content/questions/<level>-<n>.md`. Порядок файлов и вопросов в них задаёт нумерацию.

````markdown
# Текст вопроса?
@slug kebab-case-id
@topic hooks
@legacy 36
@verified react@19.2
@updated 2026-10

> Краткий ответ — 2–4 предложения, которые стоит сказать в первые 30 секунд.

Подробное объяснение: абзацы, списки, таблицы, блоки кода ```tsx.

### Подводные камни
- …

### Что спросят дальше
- …

### Ссылки
- [Название](https://react.dev/...)
````

`@topic` — один из id в `packages/content/src/topics.ts`, `@legacy` — необязательный номер вопроса из старого PDF,
`@verified` и `@updated` — необязательные: для каких версий и когда материал сверялся с документацией.
После правок запустите `npm test`: тесты проверят количество вопросов по уровням, уникальность slug,
обязательные поля, закрытые блоки кода и то, что рендер не оставляет «сырой» Markdown.

### Как добавить упражнение

Упражнения лежат в `packages/content/exercises/<тема>.yaml` — список объектов. Типы: `predict-output`, `find-bug`,
`parsons`, `fill-tokens`, `order` (`timeline` или `recipe`), `choose-tool`. Поля и проверки описаны в
`packages/content/src/exercises.ts`. Схема ловит частые ошибки: ответ вне списка вариантов, строка бага за пределами
кода, число пропусков `___` не совпадает с числом токенов. Примеры каждого типа — в `exercises/hooks.yaml`.

### Генерация упражнений с помощью Claude

Черновики упражнений по вопросам банка делает скрипт: Claude пишет упражнения (structured outputs, проверка
Zod-схемой), второй проход — ревьюер — проверяет правильность ответов, исправляет или отбрасывает спорное.
На каждый вопрос — карточка с вариантами (`quiz`, альтернатива ответу своими словами) и 2–3 практических задания.

```bash
npm run generate -w @rr/content -- --dry-run --only keys   # посмотреть промпты, без запросов
npm run generate -w @rr/content -- --only keys,rules-of-hooks
npm run generate -w @rr/content -- --topic hooks --concurrency 3
```

Ключ: скопируйте `.env.example` в `.env` в корне репозитория и впишите `ANTHROPIC_API_KEY` (файл в `.gitignore`, в приложение ключ не попадает). Подойдёт и переменная окружения или профиль `ant auth login`. В конце скрипт печатает расход токенов и стоимость.

Черновики появляются в `packages/content/exercises/drafts/<slug>.yaml` с замечаниями ревьюера в комментариях.
Вычитайте и поправьте их, затем перенесите в банк:

```bash
npm run approve -w @rr/content -- --only keys
```

`npm test` проверяет и банк, и черновики: схему, ссылки на вопросы, уникальность id.

## ИИ-проверка ответов («Объясни голосом»)

Карточку вопроса можно пройти голосом: приложение распознаёт речь на iPhone, а сервис `apps/api` оценивает ответ
по рубрике с помощью Claude Haiku 5.5 и даёт наводящие вопросы. Ключ Claude живёт только на сервере.

```bash
npm run dev -w @rr/api        # http://localhost:8787, читает .env в корне репозитория
```

- `packages/content/rubrics/` — рубрики устных ответов: пункты с весами и типичные заблуждения. Это контент: их можно
  вычитывать и править. Новые рубрики: `npm run rubrics -w @rr/content -- --only slug` (или `--batch`).
- Балл и вердикт считает код (`@rr/core/grading`), модель только отмечает раскрытые пункты и ошибки — оценка воспроизводима.
- Приложению нужен адрес API: `apps/mobile/.env` по образцу `.env.example`. Голос работает в dev build
  (`expo-speech-recognition` — нативный модуль); в Expo Go остаётся текстовый ввод.

## Аккаунты, синхронизация, лига и форум

Своя авторизация в `apps/api` (Hono + Postgres через Drizzle), без внешних сервисов.

```bash
docker compose up -d          # Postgres на localhost:5433
npm run dev -w @rr/api        # миграции применяются при старте
```

Переменные — в `.env` (см. `.env.example`): `DATABASE_URL`, `ALLOWED_ORIGINS`, `COOKIE_SECURE`.

- **Пароли** — scrypt (N=2^15) со случайной солью из `node:crypto`, сравнение за постоянное время.
- **Сессии** — случайный токен 32 байта, в базе только его SHA-256, срок 60 дней со скользящим продлением.
  Веб получает `HttpOnly; Secure; SameSite=Lax` cookie (плюс проверка `Origin` против CSRF),
  мобильное приложение — токен в ответе (`x-auth-mode: token`), хранит его в Keychain (expo-secure-store).
- **Защита входа** — лимит попыток по IP и email, одинаковый ответ для чужого email и неверного пароля.
- **Синхронизация** — прогон урока (`LessonRun` в `@rr/core`) — неизменяемое событие с id устройства.
  Приложение досылает неотправленные прогоны, сервер сохраняет их идемпотентно и сам пересчитывает XP;
  новое устройство собирает прогресс из истории функцией `foldRuns`. Конфликтов нет.
- **Лига** — XP за прогоны с понедельника, публично только ник.
- **Форум** — темы (можно привязать к вопросу банка: из урока — «Обсудить вопрос») и сообщения.
  Читать может любой, писать — после входа; автор правит и удаляет своё, модератор (`users.role = 'moderator'`)
  удаляет любые сообщения и закрывает темы. Удаление мягкое. Текст хранится как Markdown и показывается
  как текст, без вставки HTML, — XSS исключён. Лимит частоты сообщений и тем.

Схема — `apps/api/src/db/schema.ts`, миграция после её изменения: `npm run db:generate -w @rr/api`.
Тесты API поднимают Postgres в памяти (PGlite), отдельная база для них не нужна.

## Актуализация контента (радар изменений)

```bash
npm run radar -w @rr/content                    # изменения с прошлого запуска → отчёт и черновики
npm run radar -w @rr/content -- --no-generate   # только отчёт
```

Радар ищет релизы React, Next.js, TanStack Query, React Router, TypeScript и Vite (Claude с веб-поиском), сопоставляет их
с банком и пишет `packages/content/radar/<дата>.md`: что изменилось, какие вопросы задеты и как их поправить, какие
упражнения устарели, каких тем не хватает. По затронутым вопросам генератор делает черновики с учётом изменений.
Дальше — человек: правит вопросы (и `@verified`/`@updated`), вычитывает черновики, `approve --all`
и `approve --retire <id,…>` для устаревших упражнений.

## Деплой на Vercel

Веб-версия — статическое SPA в `apps/web`. В настройках проекта на Vercel укажите **Root Directory** `apps/web`:
Vercel сам определит Vite и npm workspaces, а `apps/web/vercel.json` перенаправит все пути на `index.html`.
Эта сборка — каталог, тренировка и мок-собеседование. Демо-путь в неё не входит.

## Демо на GitHub Pages

Отдельный режим сборки (`vite --mode pages`) поднимает путь обучения из мобильного приложения:
юниты, уроки и все упражнения, которые проверяются без сети (`quiz`, предсказание вывода, поиск бага,
сборка кода, пропуски, порядок, выбор инструмента). Голосовой проверки и API нет. Если у вопроса нет
карточки с вариантами, остаётся сверка с эталоном и самооценка. Прогресс, стрик и повторения пишутся
в `localStorage` (`rr-demo-progress`).

```bash
npm run dev:pages
VITE_BASE=/react-refresher-app/ npm run build:pages
```

Workflow `.github/workflows/pages.yml` публикует `apps/web/dist` при пуше в `main`. В настройках репозитория
нужен источник Pages **GitHub Actions**. Для проектного сайта база берётся из имени репозитория
(`https://<owner>.github.io/<repo>/`); для сайта вида `<owner>.github.io` база — `/`.
Неизвестные адреса отдаёт копия `index.html` как `404.html`, чтобы обновление страницы урока не ломалось.
